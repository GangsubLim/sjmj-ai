# 처리 관측은 읽기 전용이며 관문이 아니다

업로드부터 확정 직전까지 잡에 무슨 일이 있었는지 운영자가 볼 수 없다 — 강등 사유는 배포 서버
stdout에만 있고 잡 목록은 존재하지 않으며, 큐레이션에 영영 닿지 못한 잡(강등 잡·미확정 잡)은
성공한 잡과 같은 `done`이라 세어지지도 않는다. 이 구간에 **운영자용 읽기 전용 관측 표면**을 두되,
**아무 결정도 내리지 않고 어떤 상태도 바꾸지 않는다** — 이미 검수(1차)와 큐레이션(2차) 두 관문이
있고, 세 번째 결정 지점이 생기면 이 파이프라인이 애써 갈라놓은 축들(재처리 / 배제 / 배제 사유)이
같은 화면에서 다시 뭉친다. 관측이 드러내는 것은 기계가 이미 아는 것뿐이며, 고치는 일은 기존
경로로 돌아가서 한다.

## Considered Options

- **재처리·재시도 버튼을 준다**: 기각. 강등 잡에는 확정 라벨이 없어 승계할 것 자체가 없고, ADR
  0007의 재처리(확정 공급가를 행 앵커로 라벨↔그림 대응을 다시 맺는 일)와 **다른 것**이다. 같은
  버튼·같은 이름으로 묶이면 "대응 재수립"이라는 재처리의 본질이 "다시 돌리기"로 희석된다 —
  CONTEXT.md가 "재큐잉"을 금지어로 둔 바로 그 융합이다. 부수로 워커 큐를 채우는 원천도 둘이 된다.
- **폐기·배제를 준다**: 기각. 큐레이션의 배제(ADR 0006)는 **학습 후보 쌍**의 축인데 관측 대상은
  확정 전 잡이라 아직 쌍이 없다. 같은 말을 층위가 다른 두 곳에 쓰면, 0006이 "배제율이 이 가드의
  유일한 계측기"라며 지켜낸 계측이 무엇을 세는지 모르는 수가 된다.
- **별도 표면 없이 검수 화면에 진단을 얹는다**: 기각. 관측 주체는 운영자인데 현장 검수자 화면에
  파이프라인 내부 지표가 섞인다. 더 결정적으로 검수 화면은 잡 한 건짜리라, 적체·미확정처럼 **여러
  잡을 가로질러야 보이는 것**을 담을 수 없다.
- **행 오프셋까지 관측 대상에 넣는다**(행마다 크롭과 확정 라벨을 나란히 대조): 기각. 화면 성격이
  상태판에서 검수 보조로 바뀌고, 그건 큐레이션이 이미 하는 일이다.

## Consequences

- **강등 잡을 되살리는 경로는 여전히 없다.** ADR 0007의 재처리는 확정 잡을 전제하므로(앵커가
  확정 공급가다) 미확정 강등 잡에 쓸 수 없다. 관측판이 강등 잡을 드러내는 순간 "그래서 이건 어떻게
  하냐"가 따라오며, 그 경로는 이름도 결정도 아직 없다 — 이 ADR은 그것을 정하지 않는다.
- **게이트 지표를 조회 가능한 곳으로 옮기는 결정이 선행돼야 한다.** 현재 지표는 result_json 계약을
  건드리지 않으려고 launchd stdout에만 남는다. 관측판이 강등 **사유**까지 보이려면 이 결정을
  뒤집어야 하고, 어디에 실을지(계약 확장 / 별도 저장 / 로그 파싱)는 구현 시점의 별도 결정이다.
  판정 비트(`warp_ok`)만으로도 강등 **여부**는 보이므로, 지표 없이 시작하는 것도 가능하다.
- 행 오프셋 오염은 이 표면으로 탐지되지 않는다 — 화면상 완벽한 잡으로 보인다. 큐레이션 소관이며
  그 사실을 관측판이 가려선 안 된다("모두 정상"으로 읽히면 안 된다).
- 읽기 전용이라 관측판 자체가 파이프라인을 망가뜨릴 수 없고, 잡 상태를 바꾸는 권한·감사 요구가
  생기지 않는다. 대신 운영자가 문제를 발견해도 그 자리에서 손쓸 수 없다는 비용을 받아들인다.
